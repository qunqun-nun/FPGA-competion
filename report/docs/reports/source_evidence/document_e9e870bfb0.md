# HDMI 补充检查依据

本轮为电脑端代码/已归档器件资料核对；没有串口、MMIO、Overlay下载、芯片配置写入或新实板结果。当前和待审初始化器SHA与上轮一致。

## 新确认及细化

1. 当前及候选初始化器均未调用显示器EDID读取。原生库已有并导出`HdmiTx_read_edid`，固定PYNQ Python层也已有`read_edid`，因此补充显示器能力采集不一定需要重建原生库；仍需在匹配、受控的TX会话内调用并设父进程超时。EDID采集涉及DDC事务，不能宣称整个TX初始化全程只读。必须校验EDID头、逐128字节校验和、有效扩展数量与720p60支持情况。此缺口不是现阶段IDT报错的原因。

2. 当前及候选对DP159寄存器0x0A整体跳过回读。TI SN65DP159手册第37页表7中，bit2为自清除写动作位，其他位包含可读工作模式/HPD/均衡字段。可审阅的检查方案是排除bit2、比较稳定字段（候选掩码0xFB），并结合I2C_EN/PIN及RWU属性解释结果；目前只记录依据，没有改代码或声称硬件已匹配。第38页0x0B的bit1会被DDC监听更新，后续应把动态状态单列，避免将整个字节无条件全等当作唯一配置判据。不能取消全部读回保护。

3. 当前匹配官方TX驱动定义了PIO原始状态：HPD、link ready、video ready、bridge locked及溢出/欠流。`HdmiTx_connected`读的是软件缓存连接状态，须处理事件，不能冒充直接引脚测量。后续可在核实匹配Overlay、地址、PIO运行/复位状态与独占访问后，对状态寄存器做有限只读采集；PIO未运行时的0不能单独证明外部HPD低。尚未实测这些状态。

4. 原生PLL锁定函数按实际PLL类型选择CPLL/QPLL通道，没有发现固定检查错误PLL的静态问题；参考频率接口读PHY clock detector。后续需记录requested/measured参考频率、PLL锁定、STREAM_UP与bridge状态。FCLK0约100MHz仍不能替代HDMI参考/像素时钟验证。

5. IDT候选含双次相等读取检查，但这条分支尚无实板重复读取结果。原“不放宽ID检查”约束未更改，本轮没有应用候选。

## 后续顺序

先复核本次启动no-map、匹配Overlay和FCLK0及资源占用；能在有效状态下读取的HPD/芯片状态优先只读采集。然后审阅两处待审软件修正及稳定位验证，在明确ID判据边界后受控初始化、读取EDID并测试PHY/STREAM_UP。最后才检查帧缓存/AXIS画面、持续相机与真正冷启动。无测量仪器仍可完成上述软件侧定位，但不能直接测得供电、复位真实电压或TMDS波形。
