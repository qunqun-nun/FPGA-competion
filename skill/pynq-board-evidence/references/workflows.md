# 工作流

## A 上板验收

收集型号/PCB、OS/PYNQ/Python、工具链、时钟、存储、设备树、同次构建配套文件、模型和后处理契约。先读真实串口/SSH状态。新目录校验包，root核实当前内存策略。检查失败不下载、不写DDR。

记录现有服务is-enabled/is-active，正常停止访问硬件的任务，等待退出；不能只删PID和锁。加载匹配overlay，检查加载后、Runner后及持续运行时钟。初始化→真实输入→STREAM_UP→现场画面按层验证。摄像头持续覆盖规定样本数/时长，正常停止并保存计数器。

Linux退出码范式（PROJECT/PY/RUN由本项目提供，RUN先创建）：

```sh
"$PY" runtime/verify_package.py > "$RUN/verify.stdout" 2> "$RUN/verify.stderr"
rc=$?
printf '%s\n' "$rc" > "$RUN/verify.exitcode"
test "$rc" -eq 0 || exit "$rc"
```

没有verify_package.py的工程用本技能manifest/verify或项目实际验证器，不能虚构路径。网页串口不可控时使用本机工具或请操作者执行；没收到退出码就记未确认。传输分块、确认、校验；超时先查状态，不自动重复追加。凭据不入日志。

## B 模型替换

核对来源SHA/架构，解析实际图而不只信说明。区分完整输出与中间特征；有CPU末层时提取新权重/偏置与量化点，按张量名匹配。禁止复用旧CPU参数、按输出位置猜分支或二次定点缩放。

独立目录复制匹配runtime/硬件，替换模型/CPU参数并更新manifest/deployment。先真实Runner执行，再摄像头PL/HDMI完整通路。无标注只证明可执行；空预测也保存。通过后按用户需求切入口并保留原脚本和旧目录。新模型性能需重新测。

## C 开机独立运行

仅在用户要求时处理永久配置。读实际U-Boot逻辑后选择镜像机制；备份启动文件/哈希和服务状态，不能假设所有板都支持uEnv。服务显式设置Python/XRT等环境、设备就绪超时及内存预检。检查Requires间接启动和默认boot.py加载其他Overlay，不默认禁用所有系统服务。

根据硬件失败语义确定重试，不能以Restart=always替代恢复。依次验证手动启动服务、无人干预正常重启、正常关机后冷启动、拔除电脑后的现场画面。未完成就标未测。显示器先开，延长显示窗口。Power down后再让操作者断电。

## D 对照

确认开关/独立硬件构建真实可用。固定模型、固定输入、尺寸、阈值和窗口，各组重新预热，保留配置和构建哈希。缺少开关的组记未测，向硬件负责人索取接口；不能把集成配置改名冒充纯DPU/SAD/增强对照。
