# 开发验证的阶段与准入条件

## 根因路径与修改前准备

读当前 XPR/BD 实际引用、IP 文件集、RTL、约束和接口表，列出受影响层。备份会修改的文件、版本/哈希和回退步骤；不把另一个同名工程当成主工程。重现错误并保存最小输入、seed、命令和日志。明确一个根因假设，每次只改变一个可解释因素；原故障未消失或新回归出现，回到假设，不叠加猜测。无连接时做离线部分并记录板端未知。

## 验证矩阵

每个需求映射到 TB 用例、检查器、通过条件及实际证据，见 assets/verification-matrix.template.md。黄金参考从接口/算法定义推导，不能逐句翻译同一 RTL 形成相同错误。纯黑帧只能验证部分路径，应有递增像素、棋盘格、边界数值及可计算预期。

|阶段|执行与必须观察|进入下一步的条件|
|---|---|---|
|语法/展开|真实工具检查所有受影响文件、端口/位宽、顶层、参数|无错误；警告逐条处理或说明|
|模块自检|driver 输入、monitor 仅在握手采样、scoreboard 比较输出|预期事务全部收到，零 mismatch，超时能失败|
|协议断言|valid/ready、数据稳定、边界、所有权、中断等|断言启用且触发场景被覆盖；不能仅“没有报错”|
|用例/覆盖|定向边界、随机背压、多 seed、复位中断及恢复|需求用例齐全，seed 可重跑；无覆盖工具时用事件计数，不伪称覆盖率|
|集成仿真|真实相邻模块/官方 IP 模型，控制和数据同时运行|输入、请求、DDR 完成/输出按身份一致；独立 mock 不能代替真实接口验证|
|OOC 综合|局部资源、推断 RAM、锁存器及接口|局部可综合；不能据此宣布主工程通过|
|Package IP|RTL、仿真、约束文件集，component.xml 参数/总线/端口|重新封装可在新工程编辑，包含依赖；版本/实际端口对得上|
|BD/主工程|升级实际实例、生成 wrapper、Validate Design、主综合|无未连接关键接口/错误版本/旧生成文件|
|实现与 signoff|DRC、资源、setup/hold、未约束路径、CDC/复位|实际主工程满足约束；例外逐项有依据，不能靠降低严重度掩盖问题|
|回归与打包|原故障、受影响邻接模块、主链重新执行|证据与本次源码/构建关联，进入交付审查|

先进行局部综合有助于早期筛错；封装/BD 变更后还要主工程综合。用户既有“批准后进入主工程”要求持续有效，不能由此技能扩大修改范围。网表功能/时序仿真按风险补充，如需要证明厂商复位 IP 的实际常量/参数行为；语法检查不能代替模块或集成仿真。

## 接口专项必须覆盖的行为

- AXI4-Lite：AW/W 独立到达与乱序时序、B/R 背压、WSTRB 字节写、只读/写一清零、非法地址响应、中断保持与清除；不假定 AWVALID/WVALID 总是同拍。
- AXI4-Stream：只在 VALID&&READY 接受；stall 时 VALID 及 payload/sideband 保持，结合复位语义；首拍/末拍、连续帧、长短包、下游随机/长时间停顿、无丢失/重复/重排。AXI 视频 TLAST=行末，不等同通用 DMA 包末；按适配层定义检查 TUSER/SOF、行宽和帧高。
- 复位/CDC：极性、最短宽度按当前 IP 契约；异步置位同步释放、各时钟启停/锁定、帧中复位、参数原子跨域、事件不漏不重。异步时钟用不同频率/相位仿真，仍需 CDC 静态检查与约束，不能把同步仿真当亚稳态证明。
- 帧缓存/调度：读写互斥、只发布完整帧、Fresh-Frame 选择、frame_id/generation 匹配、DPU_OWNED 不被覆写、超时/丢弃/过期结果/取消后的恢复。
- 算法/像素：边界坐标、饱和/舍入/溢出、宽高最小最大、RGB 字节序/步长/填充；SAD/缩放等与独立软件金标准逐项对拍。

## 反例测试

为了证明 TB 有效，在隔离副本中注入一个可控错误（如首像素偏一、stall 时提前计数、末拍缺失），验证 scoreboard/断言/超时确实失败，再恢复后通过。不要对正在交付的源码保留注入错误。不能仅在测试结尾打印 PASS；进程退出码与断言/计数结果一致，所有 test 都有超时。

交付 TB、输入/预期输出、工具版本、运行脚本、seed、原始日志、必要波形和结果摘要。覆盖不足或官方模型不可用写明限制，不虚填仿真通过。
