# 可复用技能包

版本日期：2026-11-03。目录可整体复制；不需要原项目绝对路径，不含模型权重、厂商IP或硬件工程。

## 陌生队伍如何开始

1. 保留整个 `skill/` 目录。每个子目录的 `README.md` 面向人工，`SKILL.md` 可交给大模型读取。
2. 先选上表中与你的故障阶段相符的一项，按该项给出的终端位置和命令执行。
3. Python脚本面向Python 3.8及以上，仅使用标准库；本次实际脚本验证版本见 `validation_results.json`。PYNQ探测在子进程内尝试导入板端已有软件。电脑没有PYNQ也可输出环境缺项。在Windows中若命令为 `python`，将示例中的 `python3` 换为 `python`。
4. 校验脚本返回0表示**其声明范围内**通过；返回1表示检查失败，2表示参数/执行错误或采集不完整。报告中的未知项不得当作通过。
5. 先在PC运行 `python skill/validate_examples.py`，复核脚本的正常及失败路径。板端环境采集需在对应板卡重新运行。

## 已验证效果与证据边界

- 本轮实际完成来源视频分组的50轮训练、387张训练图片校准、90张独立测试图精度对比和DPU编译；数值见 [evidence/latest_case.json](evidence/latest_case.json)。
- 最佳验证轮为第7轮。FP32测试mAP50=76.7782%，INT8量化仿真为74.7527%；差2.0255个百分点。说明量化损失与模型跨视频泛化问题需要分开判断，不能用验证集99%左右的mAP代替独立测试结果。
- 本轮实际核验一个DPU子图、六路中间特征输出、无原先触发解析错误的切片/DFL残留，指纹逐值相符、MD5与编译器相符。**这些不代表板端推理已通过。**
- 历史板端环境、加载卡点与复位仿真结果来自用户提供的2026-10-31记录；本技能包制作时没有连接该板卡复测，也未获得该复位仿真的原始波形。
- 新增通用脚本的本机验证结果保存在 `validation_results.json`；本机测试不能替代实际板端/其他板卡验证。
- 原始结果JSON摘录、602条样本清单、真实数据审计和13项交付哈希复核见 [证据索引](evidence/README.md)。资料中的原工程路径仅作来源记录，复用脚本不依赖它们。

## 证据层级

文件哈希通过 → 软件可导入 → 图可解析 → Overlay下载成功 → 硬件指纹读回 → Runner创建 → 推理完成 → 与黄金结果对比 → 完整系统性能测试。

每一级都需要自己的日志。前一级不能推出后一级。XIR/VART/DPU各阶段只适用于使用它们的系统，普通PYNQ项目不必包含这些阶段。

## 复用限制

- 不提供通用的一键量化/上板承诺。新网络算子、位宽、DPU架构、IP版本及运行时都可能要求适配。
- `.xclbin` 是否必需由实际驱动路线决定；不因本项目需要就要求所有PYNQ项目都使用它。
- 历史使用的ReLU、387张、640尺寸、50轮、3个百分点门槛和目标指纹均是案例参数，不是所有题目的固定要求。
- 不直接替换设备树、驱动、固件，不修改模型二进制属性，不自动下载Overlay，不使用旧产物改名伪装新版本。
