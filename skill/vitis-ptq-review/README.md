# Vitis AI PTQ与精度核对

## 适用范围

Vitis AI PyTorch PTQ流程的检查工作流和评估脚本；本案例工具为3.5，目标为DPUCZDX8G。不是跨网络通用的一键量化器，也不是通用PYNQ Skill。

## 使用方法

1. 在**训练PC**固定数据划分、权重SHA-256、模型结构、输入尺寸和黄金预处理。断点须含优化器、原训练参数及epoch，恢复到总轮数而非额外追加轮数。ReLU替换应在训练/微调前完成；不能训练后直接替换并声称精度不变。
2. 在**量化容器**记录Python、PyTorch、pytorch_nndct和模型库版本。加载 `nn.Module`，不要把返回tuple误当module。输入参数使用 `(dummy,)`。校准使用真实且有代表性的训练样本；本例使用全部387张，不为凑500而重复图片。
3. 校准和测试采用同一模型构图、权重和量化设置。`quant_info.json`是校准结果，不是传给 `quant_config_file` 的自定义配置模板。CLE与fast finetune不是同一技术；开启与否需单独记录，本例开启CLE但未执行fast finetune。
4. 在**同一测试集**，以同一预处理、阈值、NMS和框解码评价FP32及量化仿真结果。DFL等后处理保留CPU时，仿真也应按对应边界解码。
5. 使用本包证据样例，在**PC终端**可直接验证精度门槛：

```bash
python3 skill/vitis-ptq-review/scripts/compare_map.py --input skill/evidence/latest_case.json --max-drop-pp 3
```

自己的输入JSON需包含 `fp32`、`int8_cpu` 两个字典，每项均有 `metrics/mAP50(B)` 与 `metrics/mAP50-95(B)`，数值范围为0到1。门槛单位是**百分点**；脚本只比较数值，不能证明两个结果使用了相同数据，需人工核对样本清单及评估参数。

6. 在**编译容器**从当前图选择输出节点；根据真实硬件架构编译。核验DPU子图数量、输出形状/名称/量化属性、实际指纹和MD5；保存compile命令、日志和模型SHA-256。本例单DPU/六输出约束来自特定加载器，不适用于所有网络。
7. 交付时分别标注仿真精度、编译结构、板端执行状态。六路中间特征不等于检测框；CPU末层参数必须与本次权重配套。

## 可复用提示词

> 请逐项对照校准、FP32测试、量化仿真和板端输入输出契约。列出每处颜色空间、resize、补边、通道顺序、归一化、定点缩放、DFL和NMS的执行位置与次数。找出首个不等价环节，再做最小修改并重测。不要用测试集调权重，不复用旧图节点编号，不把编译成功写成上板成功。

## 来源与已验证效果

见 [pitfalls.md](references/pitfalls.md)。本轮50轮训练后最佳为第7轮；真实90图测试FP32 mAP50/mAP50–95为76.7782%/62.8616%，INT8仿真74.7527%/61.1937%。编译指纹与历史目标相同，结构及文件校验通过。原始数值与哈希摘录在 `../evidence/latest_case.json`。

## 失效条件

网络头API或NNDCT版本改变、目标DPU不同、校准分布偏移、输入尺寸变化、后处理边界变化时须重新适配。3个百分点是本例门槛，不是行业统一标准；通过门槛不表示绝对精度满足任务。本例测试召回率只有61.11%，量化前已存在，不能靠修复缩放解释全部泛化问题。未执行板端mAP或性能测试。
