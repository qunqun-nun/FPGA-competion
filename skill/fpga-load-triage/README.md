# FPGA加载卡点与硬件交接

## 适用范围和方法

适用于PYNQ/Overlay加载及XRT运行路线的卡住问题。分层方法可迁移；具体DPU/XRT复位案例与本项目有关，不将整项冒充通用PYNQ。

在**分析电脑**填写 `assets/handoff.template.md`；在**板端终端**收集最后成功日志和内核消息。不要把所有步骤塞进一个无法判断停在哪的脚本。每步打印开始/结束及时间，先核对文件再解析，再加载；涉及硬件配置时先确保该阶段已获授权且文件匹配。

|里程碑|能证明什么|不能证明什么|
|PACKAGE_HASHES_OK|清单内文件身份|文件匹配、驱动兼容|
|模型解析成功（若有）|当前图解析库能读|Runner及硬件执行|
|PYNQ设备枚举成功|软件发现设备|目标Overlay已配置|
|OVERLAY_DOWNLOAD_OK|本次加载调用返回|DPU/自定义IP算对|
|真实硬件标识读回|读到该设计真实寄存器值|输入输出数值正确|
|Runner创建（若使用）|执行后端创建成功|任务能完成|
|执行成功|一次任务返回|黄金参考一致、系统性能达标|

XRT分解日志可包括xclOpen、xclLockDevice、xclLoadXclBin；这些仅适用于该运行路线。子进程timeout不保证能解除内核驱动的阻塞，更不能说明硬件已恢复。

## 提示词

> 请按里程碑识别最早未完成阶段。列“直接观察、推断、未知、下一项可证伪测试”。若最后只有中断初始化失败，不要立刻认定中断是唯一根因；同时核对时钟、复位、AXI控制通路和驱动版本。凡需硬件修改，给构建方可操作的修改点、依据、重新交付文件和验收步骤。

## 来源、已验证效果与失效条件

- 来源：用户2026-10-31记录中，V0.15文件校验、模型解析及文件推算指纹一致；xclOpen有效、xclLockDevice返回0，随后xclLoadXclBin不返回。
- 该记录进一步报告：proc_sys_reset的aux_reset_in配置低有效却接常量0；使用交付功能网表仿真得到interconnect_aresetn持续0，改1后释放，标记RESET_POLARITY_PROOF_PASS。这是**该配置的缺陷**，不是所有proc_sys_reset实例的固定极性。
- 已验证效果：历史记录把问题从笼统“模型不能跑”缩小到硬件控制通路复位缺陷；本包未重新执行原始网表仿真，也没有修复后板端成功证据。具体案例来源与边界见 `../evidence/latest_case.json`。
- 失效条件：没有同版本HWH/XCI/网表、时序/仿真记录不完整、实际bit并非检查的版本，均不能沿用复位结论；修复复位不自动排除中断、驱动或时钟问题。
- 需构建方同次重建并交付匹配bit/hwh/xclbin（仅适用于所选XRT路线）、构建日志和哈希；只有模型量化环境不能修硬件复位。
