# 视频数据来源分组审计

## 适用范围与方法

用于视频抽帧检测、分类等数据集；不是PYNQ专属技能。不从文件名猜来源，要求显式CSV，首行为 `path,split,group`，示例见 `assets/samples.example.csv`。path相对于 `--root`，group是来源视频ID，split为train/valid/test。

在**PC终端**，准备自己的manifest后执行：

```bash
python3 skill/video-group-audit/scripts/audit_groups.py --root dataset --manifest samples.csv --out split_audit.json
```

脚本检查文件存在、记录重复、来源组跨集合和文件SHA-256跨集合；发现任意一项即返回1。不修改数据、不重新分组。按组切分时应兼顾类别和拍摄条件；测试组在训练前固定，不根据测试精度反复更换。

## 提示词与案例

> 根据样本清单，先核对来源ID是否完整且可靠，再按视频组划分训练、验证和测试。列每组样本数、类分布及场景覆盖。检查跨集合来源和完全重复；没有通过时不要启动训练。保留划分清单，不用测试集选择epoch。最后报告验证与测试差异，不把高验证mAP解释成跨背景泛化已通过。

## 来源、已验证效果、失效条件

- 来源：原数据按帧随机分配造成同视频跨集，验证精度很高。用户要求停止后，改为四段视频整组分配，训练387、验证125、测试90；重新完成50轮。
- 已验证效果：本轮来源组无跨集、预处理后PNG文件无完全重复跨集。验证最佳mAP50约98.98%，但独立视频测试只有76.78%，揭示验证分数不能代替跨视频效果。
- 脚本接口要求标准化CSV；当前项目的 `_mp4` 前缀提取只用于已有案例，不能假定其他队伍也采用此命名。
- 失效条件：视频ID错误或同源视频被拆成不同ID；同场景不同录像仍强相关；重新编码导致像素相同但字节不同。脚本只检测文件字节完全重复，不是感知去重；可对统一预处理后的图像补充审计，但仍不证明完全无泄漏。
- 少数来源视频可能导致结果方差很大；需要更多独立来源或按组交叉验证才能得到更稳健结论，本包未替其他数据执行此验证。
