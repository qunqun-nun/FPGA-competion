测试日期：2026-11-03（北京时间）。板卡系统时间为2022年，原始时间保留；采样窗口用单调时钟计算。

本次完成现有集成配置的持续 USB 摄像头性能测试。以下均为实测，不沿用截图中的示例数值。没有带标注且独立于训练的数据集，没有高速录像；本轮没有检出目标，因此没有验证有效 SAD 跟踪。

预热10次，有效任务120次，全部130次正常完成。有效窗口为第10次结果被PL接受之后至第130次结果被PL接受，共 **83.934067500秒**，期间成功摄像头取帧1752次。软件请求上限5 FPS，并非达到5 FPS。输入为摄像头，经灰度化/缩放至640×480；PL Letterbox上下各80行填充值114，DPU输入1×640×640×3 INT8，fix_point=7。摄像头请求640×480，未获取原生视频格式/驱动标称FPS；处理尺寸已固定并逐帧校验。USB设备Microdia 0c45:6340。

阈值：confidence=0.25、NMS IoU=0.45。没有人为注入检测结果。当前无目标，实际每帧触发DPU请求，130帧/130请求；文档中SAD有效跟踪后每15次跟踪结果重检的机制本轮未触发，不能称作已验证15帧检测间隔。

## 分阶段耗时

每项N=120，单位ms。P95采用排序后第ceil(0.95×N)=114个样本（最近秩法）。计时为Python perf_counter_ns；不扣除探针开销，不声称硬实时最坏边界。

| 阶段 | 平均 | P95 |
|---|---:|---:|
| 输入张量准备（量化/归一化/连续数组） | 40.262836 | 42.907160 |
| DPU任务提交至wait成功返回 | 13.995535 | 14.277670 |
| CPU六路末层卷积（额外列出） | 227.831265 | 239.396660 |
| 解码/NMS/坐标还原 | 7.730054 | 8.262970 |
| 完整检测调用（输入张量+DPU+CPU末层+后处理） | 290.259402 | 304.255130 |
| 结果发布调用至PL接受（提交计数变化） | 0.355671 | 0.375980 |
| 软件首次读取到请求至PL接受 | 341.269500 | 357.176420 |

“完整检测调用”不含摄像头取帧、缩放、PL传输、DDR读取校验、时钟/HDMI监督和日志等整机循环开销。其耗时倒数不是整机FPS，也不是显示延迟。本模型有六路CPU末层，DPU约14ms不能代表完整检测约290ms；CPU末层是已测检测调用中耗时最大的阶段。

检测请求生成后等待软件处理的时间：**未测**。现有软件只能记录首次观察到请求的时间，没有与同一时钟对齐的硬件请求生成时间戳。最后一行已包含DDR读取和校验等后续工作，不包含未知的首次观察前等待；不得当作队列等待时间或显示延迟。

## 计数器、丢帧与运行状态

有效窗口PL completed增加120；dropped、stale_results、aborted、profiler_timeouts均增加0；各任务error均0。全程130条输出记录均stream_up，最终130 submitted / completed / inferences / result_commits，真实进程退出码0，HDMI清理到CLOSED。

摄像头采用后台持续取最新帧，应用只消费较慢的一部分：摄像头成功取帧数量与处理数量不同。PL dropped=0仅表示PL层计数，不表示摄像头到显示端逐帧无丢弃。未采集UVC序号，不能提供传感器/USB传输层丢帧率。
