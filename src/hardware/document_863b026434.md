# V017 IDT 时钟使能平台修复

状态仍为候选联调包。新增平台输出不等于已经生成可部署的新整机 bit/xclbin，也不代表 HDMI 软件阻塞或全链实板验收已完成。

本次仅在现有 `v014_main_project_20261024/project/fengyan_pl.xpr` 副本修改：新增输出 `IDT_8T49N241_RST_OUT`，连接原有 1-bit `const_one/dout`；在现有 HDMI XDC 添加 M12 / LVCMOS33 约束；更新 BD、wrapper 及 V017 平台元数据。没有新建 Vivado 工程，没有 launch 综合/实现或 v++。

板卡依据：[AMD UG1267 v1.1 第61页](https://docs.amd.com/api/khub/documents/g76en4BfB6qIp2gHDRkQxg/content) 指定时钟芯片复位/使能网络必须驱动高电平，并接 FPGA bank87 的 M12。[PYNQ 官方 base.xdc](https://github.com/Xilinx/PYNQ/blob/master/boards/zcu104/base/vivado/constraints/base.xdc) 使用 M12、LVCMOS33；[官方 base.py](https://github.com/Xilinx/PYNQ/blob/master/boards/zcu104/base/base.py) 在初始化外部时钟芯片前写 1 解除复位。本次常量高电平修复使能缺口，不增加软件控制该引脚的能力；I2C 时钟编程及 TX/PHY 初始化仍由软件完成。

`change_backup` 仅备份改前的 XPR、BD、顶层 wrapper、HDMI XDC 四份文件，保持原相对位置，哈希在 `change_backup/affected_files.json`。修改前先通过复制替换解除静态主工程内所有共享硬链接，记录在 `logs/v017_detached_hardlinks.json`。旧最终链接工程与旧 XSA 的改前哈希在 `logs/v017_protected_before.json`；V016 原件始终只读。

相对路径入口：

```powershell
# 首次备份已经做过，不要覆盖 change_backup。
powershell -NoProfile -ExecutionPolicy Bypass -File .\run_v017_platform.ps1 -Stage patch
powershell -NoProfile -ExecutionPolicy Bypass -File .\run_v017_platform.ps1 -Stage xpfm
```

内部对应 `scripts/patch_v017_idt_reset.tcl`、`scripts/generate_v017_xpfm.tcl`，均从脚本位置推导根目录。默认临时 W:/subst，盘符已占用会停止。可用 `-Drive Q` 指定另一个空闲盘符。XSA 输出 `platform/fengyan_v017_extensible.xsa`；XPFM 位于 `platform/generated_v017/fengyan_v017_zcu104/export/fengyan_v017_zcu104/fengyan_v017_zcu104.xpfm`。XPFM 脚本在已有同名输出时停止，避免覆盖已交付平台。

路径随运行时映射生成；换盘符后须重新生成配置。没有映射时，可省略参数生成实际绝对路径配置，但本机中文长路径环境优先使用 subst。对应 v++ 选项语法依据：[UG1393 2022.2](https://docs.amd.com/r/2022.2-English/ug1393-vitis-application-acceleration/Using-the-vivado-and-advanced-Options)。

后续由主代理执行真实的新 `v++ --link --target hw --platform <V017 XPFM> --config <增量配置> <现有 XO>`，使用全新输出目录。旧 DCP 仅供增量参考，不能作为新结果交付。若增量不可用、失败或时序不满足，使用 `link_v017_normal.cfg` 重新正常实现，保留失败日志并换干净输出目录。

最终还必须对新 routed DCP 做时序、DRC、路由等检查，核对新 bit/HWH/xclbin 的同次配套（包括 xclbin 内嵌 bit 哈希），必要时再导出新最终 fixed XSA；不能沿用旧最终 XSA 证明新增 M12 已进入实板 bit。HDMI evaluation 和软件初始化限制仍存在。

回退时先关闭 Vivado，将四份备份文件复制到临时文件后替换回原相对路径（避免覆盖共享硬链接）。当前 `.gen` 是派生输出，回退 BD/wrapper 后需要重新生成相应输出产品；新增 V017 平台应保持独立归档或标记停用，不要与旧平台混用。
